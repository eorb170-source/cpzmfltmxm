# 업무 체크리스트

여러 업무 점검을 데일리/위클리/먼슬리/연간 주기로 관리하고, 예정 시간이 지나도 체크되지 않은 업무는 데스크톱 알림으로 알려주는 로컬 데스크톱 앱입니다. 완료 이력을 기간별로 집계해 연봉협상 자료(PDF)로 바로 내보낼 수 있습니다.

## 주요 기능

- **오늘의 체크리스트**: 데일리/위클리/먼슬리/연간/단발성 업무를 주기별로 구분해 오늘 해야 할 항목만 보여줍니다.
- **반복 업무 관리**: 업무마다 반복 유형(매일 / 매주 특정 요일 / 매월 특정 일자 / 매년 특정 날짜 / 1회성)과 분류(카테고리)를 지정할 수 있습니다.
- **예정 시간 + 미체크 알림**: 업무에 예정 시간을 설정하면, 그 시간이 지나도 체크가 안 되어 있을 경우 설정한 간격으로 반복해서 데스크톱 알림을 보냅니다.
- **이력 조회**: 기간/상태(완료·대기·미완료)별로 지난 수행 기록을 조회합니다.
- **연봉협상 자료**: 기간을 선택하면 분류별·업무별 완료 횟수를 집계해 표로 보여주고, 그대로 PDF 파일로 저장할 수 있습니다.
- **데이터 저장**: 브라우저 저장소가 아닌 로컬 SQLite DB 파일(사용자 데이터 폴더)에 저장되어, 앱을 껐다 켜도 안전하게 유지됩니다. (`sql.js` 기반이라 Visual Studio Build Tools 같은 별도 컴파일 도구 없이 `npm install`만으로 설치됩니다.)

## 실행 방법

```bash
npm install
npm start
```

## 배포용 패키징 (설치 파일 생성)

```bash
npm run dist
```

Windows에서 실행하면 `dist/` 폴더에 `업무 체크리스트 Setup 1.0.0.exe` 같은 설치 파일이 생성됩니다. 이 파일을 더블클릭해서 설치하면, `npm start`로 켜는 개발용 실행과 달리 시작 메뉴/바탕화면 아이콘이 생기고 "프로그램 추가/제거"에도 정상적으로 등록되는 **진짜 설치된 프로그램**이 됩니다.

(macOS는 dmg, Linux는 AppImage로 생성됩니다.)

## 자동 업데이트 (반드시 최신 버전으로 유지)

이 앱은 **GitHub Releases**를 업데이트 서버로 사용합니다. 즉, 이 저장소(`eorb170-source/cpzmfltmxm`)에 새 버전을 릴리스로 올리면, 설치되어 있는 프로그램이 실행될 때(그리고 실행 중에도 4시간마다) 자동으로 감지해서 **다운로드 → 사용자 동의 없이 자동으로 재시작하며 설치**합니다. 화면 위에 진행 상황이 배너로 표시됩니다.

> ⚠️ 자동 업데이트는 `npm start`(개발 모드)에서는 동작하지 않고, `npm run dist`로 만든 **설치된(installed) 프로그램에서만** 동작합니다.

### 새 버전을 배포하는 방법 (유지보수자용)

1. `package.json`의 `"version"` 값을 올립니다 (예: `1.0.0` → `1.0.1`). 이 버전 번호로 업데이트 여부를 판단하므로 **반드시 올려야** 합니다.
2. GitHub에 올릴 수 있는 권한이 있는 [Personal Access Token](https://github.com/settings/tokens)을 하나 만듭니다 (권한 범위: `repo`).
3. 터미널에서 토큰을 환경 변수로 설정하고 릴리스 명령을 실행합니다.

   Windows(cmd) 기준:
   ```
   set GH_TOKEN=여기에_토큰_붙여넣기
   npm run release
   ```

   이 명령은 설치 파일을 빌드하고, GitHub 저장소에 새 릴리스를 만들어 설치 파일과 업데이트 정보(`latest.yml`)를 자동으로 업로드합니다.
4. 이후 사용자 PC에서 실행 중이거나 다음에 실행되는 프로그램이 새 버전을 자동으로 받아 설치합니다.

`npm run dist`(로컬 테스트용 빌드, 릴리스 업로드 안 함)와 `npm run release`(실제 배포용, GitHub Releases에 업로드)를 상황에 맞게 구분해서 사용하세요.

### 스키마(데이터 구조)를 바꾸는 새 버전을 낼 때

나중에 업무 항목에 새 필드를 추가하는 등 저장 구조 자체를 바꾸는 업데이트를 낸다면, 이미 설치해서 데이터를 쌓아둔 사용자들의 로컬 DB가 깨지지 않도록 **`electron/db.js` 맨 위의 `SCHEMA_VERSION`을 1 올리고, `MIGRATIONS` 객체에 같은 번호로 변경 내용(예: `ALTER TABLE ...`)을 추가**해야 합니다. 이렇게 하면 자동 업데이트로 새 버전을 받은 사용자의 기존 데이터가 안전하게 새 구조로 옮겨지고, 새로 설치하는 사용자는 처음부터 최신 구조로 시작합니다. (이 자리에 예시 주석을 남겨뒀습니다.)

## 다른 사람에게 배포할 때 내 데이터가 넘어가지 않는지

**설치 파일(.exe) 자체에는 여러분의 업무 데이터가 전혀 들어있지 않습니다.** 업무/이력 데이터는 설치 파일과 별개로 각 PC의 사용자 계정 폴더(Windows 기준 `%APPDATA%\work-checklist\`)에 저장되고, `npm run dist`/`npm run release`로 만드는 설치 파일에는 프로그램 코드만 포함됩니다. 그래서 만든 설치 파일을 다른 사람 PC에 설치하면 그 사람은 항상 빈 상태로 시작합니다.

다만 **내가 쓰던 PC를 그대로 다른 사람에게 넘기는 경우**(설치 파일 전달이 아니라 PC 자체를 인계하는 경우)에는 이미 저장된 데이터가 그대로 남아있으니, 이럴 때는 넘기기 전에 **설정 탭 → "모든 데이터 초기화"** 버튼으로 업무/이력을 지워주세요. (알림·기본 설정 값은 유지되고 업무 목록과 완료 이력만 삭제됩니다.)

## 지금 실행 중인 버전 확인하기

설정 탭에 **현재 버전**이 표시되고, **"지금 업데이트 확인"** 버튼으로 자동 업데이트를 기다리지 않고 바로 확인할 수 있습니다. 자동 업데이트로 재시작된 뒤 이 화면의 버전 번호가 바뀌었는지 보면 새 버전이 실제로 적용됐는지 확인할 수 있습니다.

## 폴더 구조

```
electron/
  main.js        # 앱 진입점, IPC 핸들러, 창 생성
  preload.js     # 렌더러에 안전하게 노출되는 API
  db.js          # SQLite 스키마 및 초기화
  scheduler.js   # 반복 업무 인스턴스 생성 + 미체크 알림 로직
  reports.js     # 연봉협상 자료(집계/HTML/PDF) 생성 로직
  dateUtils.js   # 날짜/반복 규칙 계산 유틸
  updater.js     # GitHub Releases 기반 자동 업데이트(강제 적용) 로직
renderer/
  index.html     # 화면 구조 (탭: 오늘/업무 관리/이력/연봉협상 자료/설정)
  app.js         # 화면 로직
  styles.css     # 스타일
```

## 데이터 모델 요약

- `tasks`: 업무 템플릿(제목, 분류, 반복 유형/설정, 예정 시간, 알림 사용 여부·간격)
- `task_instances`: 특정 날짜에 실제로 발생한 업무 건(완료 여부, 완료 시각, 알림 발송 이력)
- `settings`: 전역 알림 on/off, 기본 알림 간격 등

앱이 켜져 있는 동안 1분마다 다음을 수행합니다.
1. 날짜가 바뀌면 지난 날의 미체크 항목을 "미완료(경과)"로 표시하고, 오늘 날짜에 해당하는 반복 업무 인스턴스를 새로 생성합니다.
2. 예정 시간이 지났는데 아직 체크되지 않은 업무가 있으면(알림이 켜져 있는 경우) 데스크톱 알림을 보냅니다. 이후에도 체크되지 않으면 업무별로 설정한 간격마다 다시 알립니다.

## 추가로 고려해볼 만한 아이디어

앱을 쓰면서 필요해지면 추가로 요청해 주세요. 예를 들어:
- 특정 업무를 완료할 때마다 성과/메모를 남기고, 연봉협상 자료에 하이라이트로 포함하기
- 업무 항목에 우선순위나 소요 시간을 기록해 통계 내기
- 여러 대의 PC/모바일에서 데이터를 동기화하기(현재는 이 PC의 로컬 DB에만 저장됩니다)
- 완료율이 낮은 반복 업무를 자동으로 강조 표시하기
